# 実装レビュー判定

この文書は、レビュー開始条件とレビュー集約条件を定義する。

## 用途

- 対象差分のレビュー開始可否を判定する。
- 複数レビュー結果を集約して最終判定する。

## 必須レビュー担当

- 実装差分（executable behavior を含む変更）:
  - `構造レビュー担当`
  - `運用整合レビュー担当`
  - `セキュリティレビュー担当`
  - `仕様適合レビュー担当`
- 文書是正・文書主成果物:
  - `運用整合レビュー担当`
  - `参照整合レビュー担当`
- 追加で高リスク変更を含む場合は `セキュリティレビュー担当` を必須化する。

## レビュー開始条件

- 対象差分識別子がある。
- 最低1件の確認記録がある。
- 必須レビュー担当が割り当て済みである。
- 起動不能役割がある場合は、`対象役割`、`起動失敗理由`、`起動失敗証跡`、`代替実行者`、`代替実行者 agent/run 識別子`、`no-reuse 規則充足根拠` の6項目を同一変更セットへ記録する。
- 役割別フォールバックで記録する `代替実行者` は、現在のオーケストレーター（現在の実行者）を指定してはならない。

## 集約規則

- 1件でも `不合格` があれば未完了。
- `要修正` があれば修正後に再レビュー。
- 必須担当が全員 `合格` の場合のみ `集約後レビュー判定: 合格`。
- `主成果物: 実コード差分` の作業項目で `集約後レビュー判定: 合格` とする場合、合否判定を要約だけで決めてはならない。作業定義文書の `規約違反の解消対象` と `構造完了条件` に対し、現行コード追跡で未解消項目が残っていないことを確認できる場合に限り `合格` とできる。

## コミット連動規則

- コミット関連作業は `集約後レビュー判定` の記録後に開始できる。
- 個別メッセージやチャット上の宣言のみで完了扱いにしてはならない。
