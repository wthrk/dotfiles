# 実装レビュー判定

この文書は、実装レビューの開始可否と複数レビュー結果の集約判定の正本である。

## 用途

- 実装差分のレビューを開始できるか判定する。
- 複数レビュー担当の結果をどう集約するか判定する。

## 必須レビュー担当

- `構造レビュー担当`
- `運用整合レビュー担当`
- `セキュリティレビュー担当`
- `仕様適合レビュー担当`
- `参照整合レビュー担当`
  - 文書構成変更、タスク運用変更、スキル変更、`AGENTS.md` 変更を含む場合に必須

## レビュー開始条件

- 対象差分識別子がある。
- 実装担当の確認証跡がある。
- 次回着手前オーケストレーション記録に複数レビュー担当の役割一覧がある。
- 実装担当の `agent/run` 識別子がある。
- 各レビュー担当の `agent/run` 識別子がある。
- 起動できないレビュー役割がある場合は、役割別フォールバック記録（`対象役割`、`起動失敗理由`、`起動失敗証跡`、`代替実行者`、`代替実行者 agent/run 識別子`、`no-reuse 規則充足根拠` の6項目）がある。
- executable behavior を含む作業では、対象コードパスまたは直接必要な隣接コードパスに実コード差分がある。

## 各レビュー担当の判定責務

- `構造レビュー担当`
  - 責務境界
  - 依存方向
  - 公開インターフェース境界
  - 作業定義文書の `構造完了条件` と `レビュー合格条件`
- `運用整合レビュー担当`
  - 状態遷移
  - 確認証跡
  - 台帳更新
  - 粗粒度進捗更新
  - 再開条件
- `セキュリティレビュー担当`
  - 秘密値
  - 認証情報
  - 権限境界
  - 永続化
  - ログ、引数、一時ファイル、標準出力への漏えい
  - 危険な失敗時挙動
- `仕様適合レビュー担当`
  - 仕様書
  - 設計書
  - 作業定義文書
  - 停止条件
  - 成功条件
  - 利用者向け挙動
- `参照整合レビュー担当`
  - パス
  - 導線
  - 正本参照
  - グローバル文書への領域固定前提の混入
  - skill と docs の重複

## 集約規則

- いずれか 1 人でも `不合格` を返した場合、`レビュー` は未完了のままとする。
- `要修正` がある場合、修正後に全レビュー担当へ再確認を回す。
- 役割別フォールバックでレビューした場合も、各必須役割の判定行、役割ごとの `agent/run` 識別子、フォールバック理由・証跡を同一記録へ残さない限り集約してはならない。
- 全レビュー担当が `合格` の場合に限り、集約後の `レビュー判定` を `合格` にできる。
