# タスク完了判定

この文書は、作業項目の `完了` 遷移判定の正本である。

## 完了判定の前提

- `確認` が完了している。
- `レビュー` が完了し、必要なレビュー担当の判定がそろっている。
- `必要時の後続対応` が `完了` または `完了（不要）` で閉じている。
- 主成果物が作業定義文書の要求を満たしている。

## 実装作業の追加条件

- executable behavior を含む作業では、対象コードパスまたは直接必要な隣接コードパスに実コード差分がある。
- 文書差分のみの場合、実装作業の `完了` 判定には使えない。

## 粗粒度進捗との整合

- 粗粒度 issue / phase を持つ作業では、対応する `issue-*.md` の整合を同一変更または追跡可能な更新で満たす。
- 下位タスクの件数集計だけで粗粒度完了を判定してはならない。

## 判定失効条件

次のいずれかが欠落する前進遷移は無効とする。

- 対象差分識別子
- 確認手順と結果
- レビュー担当ごとの判定
- 実装担当の `agent/run` 識別子
- レビュー担当ごとの `agent/run` 識別子
- 進捗判定担当の `agent/run` 識別子
- 役割別フォールバック記録（フォールバックがある場合。`対象役割`、`起動失敗理由`、`起動失敗証跡`、`代替実行者`、`代替実行者 agent/run 識別子`、`no-reuse 規則充足根拠` の6項目を必須で含む）
- 集約後のレビュー判定
- 未実施理由（未実施がある場合）
