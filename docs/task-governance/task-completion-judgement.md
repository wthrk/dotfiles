# タスク完了判定

この文書は、作業項目を `完了` へ遷移できる条件を定義する。

## 完了判定の前提

- `必要レビュー役割` は `docs/task-governance/implementation-review-judgement.md` の定義に拘束され、本書で再定義しない。
- 主成果物の差分が存在する。
- 必要レビュー役割の判定がそろい、集約後レビュー判定が `合格`。
- 作業定義文書の完了条件を満たす。

## 実装作業の追加条件

- executable behavior を含む作業では、関連コードに実コード差分がある。
- 文書差分のみは、実装作業の完了根拠に使わない。
- `主成果物: 実コード差分` の作業項目では、表面的な進捗指標だけを根拠に `完了` 判定してはならない。
- 作業定義文書の `規約違反の解消対象` と `構造完了条件` について、現行コード追跡に基づき未解消項目が残らないことをレビュー記録上で確認できる場合に限り `完了` 判定できる。

## 文書作業の扱い

- 文書主成果物の作業は、文書差分とレビュー合格で完了判定できる。
- 粗粒度進捗文書の同時更新は任意とする。

## 共通要件と領域要件の優先

- 本文書の完了要件は共通の下限であり、領域固有文書がより厳格な完了条件や証跡条件を定める場合は、領域固有要件を優先して適用する。
- 共通要件を満たしていても、領域固有要件が未充足なら `完了` 判定してはならない。

## 判定失効条件

次のいずれかが欠落する場合、`完了` 判定を無効とする。

- 対象差分識別子
- 集約後レビュー判定
- 必須レビュー役割の判定記録
- 共通規約または領域固有規約で必須化された確認結果

## コミット許可条件

- コミットは、対象差分、必須レビュー役割の結果、集約後レビュー判定 `合格` の記録を満たす場合に許可する。
- 文書是正では、レビュー記録を主記録として扱い、無関係な台帳同期は要求しない。
- 文書是正では、review/confirmation 記録に exact tracked-file set、file-count、current-cycle 文言、対象パス列挙、台帳間同期の固定一致を要求しない。変更要約、実行した確認、レビュー verdict が追跡できれば足りる。
- 口頭・チャットのみの合格表明は許可根拠にならない。
