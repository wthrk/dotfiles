# 進捗判定規則

この文書は、進捗前進の最小条件を定義する。

## 基本状態

- `未開始`
- `進行中`
- `完了`

## ワークフロー状態との対応

- `未開始` は `workflow.md` の `S0: 開始待ち` に対応する。
- `進行中` は `workflow.md` の `S1: 実装中`、`S2: レビュー中`、`S3: レビュー集約完了` に対応する。
- `workflow.md` の `S4: コミット着手可` はコミット関連作業の開始可否を示す状態であり、作業項目の `完了` 判定と同一視しない。

## 前進条件

- `進行中` への遷移は、対象作業と担当が識別できること。
- `task-list-outside` への分類で開始する場合は、`docs/task-governance/review-artifacts/outside-ledger-intake.md` の最小記録（分類と責任境界）を残していること。
- `レビュー` 前進は、遷移段階ごとに本書「必須証跡（最小）」で定義した要件を満たすこと。
- executable behavior を含む作業では、関連コードに実コード差分があること。
- 文書是正は文書差分のみで前進できる。

## 必須証跡（最小）

`確認`、`レビュー`、`実装状態` の前進では次を必須とする。

- `確認` 前進: 対象差分識別子
- `レビュー` 前進（`S1 -> S2`）: 対象差分識別子に紐づく `確認` 記録
- `レビュー` 前進（`S2 -> S3`）: レビュー担当ごとの判定、集約後レビュー判定
- `実装状態` 前進: 対象差分識別子（`S2 -> S3` を伴う前進では、レビュー担当ごとの判定と集約後レビュー判定も必要）

上記以外の運用記録（詳細手順、粗粒度同期、重複台帳反映）は任意とする。

## 共通要件と領域要件の優先

- 本文書の最小証跡要件は下限であり、領域固有文書がより厳格な証跡・判定条件を定める場合は、領域固有要件を優先して適用する。
- 共通要件を満たしていても、領域固有要件が未充足なら前進判定してはならない。

## コミット可否との連動

- コミット関連作業は、対象差分、必須レビュー役割の結果、`集約後レビュー判定: 合格` の記録を満たすまで開始してはならない。
- 文書是正では、レビュー記録が主記録であり、無関係な台帳前進や粗粒度進捗同期を必須にしない。
- チャットや口頭のみの合格表明は無効とする。
