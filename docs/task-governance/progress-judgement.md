# 進捗判定規則

この文書は、進捗前進の最小条件を定義する。

## 基本状態

- `未開始`
- `進行中`
- `完了`

## ワークフロー状態との対応

- `未開始` は `workflow.md` の `S0: 開始待ち` に対応する。
- `進行中` は `S1: 実装中`、`S2: レビュー中`、`S3: レビュー集約完了` に対応する。
- `S4: コミット着手可` はコミット関連作業の開始可否であり、完了判定と同一ではない。

## 前進条件

- `進行中` への遷移は、対象作業と担当が識別できること。
- レビュー前進は、本書の必須根拠を満たすこと。
- executable behavior を含む作業では、関連コードに実コード差分があること。
- 文書是正は文書差分のみで前進できる。

## 必須根拠

- `確認` 前進: 対象差分識別子。
- `レビュー` 前進（`S1 -> S2`）: 対象差分識別子に紐づく確認結果。
- `レビュー` 前進（`S2 -> S3`）: レビュー担当ごとの判定、集約後レビュー判定。
- `実装状態` 前進: 対象差分識別子。`S2 -> S3` を伴う場合はレビュー担当ごとの判定と集約後レビュー判定。

詳細手順、粗粒度同期、重複台帳反映、補助記録の exact 同期は前進 gate にしない。

## 共通要件と領域要件

- 本文書の要件は下限であり、領域固有文書または指定 issue / PR がより厳格な実検証・判定条件を定める場合はそれを優先する。
- 補助記録の exact 同期だけを厳格条件として復活させてはならない。

## コミット可否との連動

- コミット関連作業は、対象差分、必須レビュー役割の結果、`集約後レビュー判定: 合格` の記録を満たすまで開始してはならない。
- チャットや口頭のみの合格表明は無効とする。
