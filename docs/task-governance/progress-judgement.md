# 進捗判定規則

この文書は、状態遷移、前進条件、証跡要件を定義する。

## 基本状態

- `未開始`: 開始条件が未充足、または主成果物に着手していない。
- `進行中`: 開始条件を満たし、主成果物の差分作成または確認中である。
- `完了`: [task-completion-judgement.md](task-completion-judgement.md#タスク完了判定) の要件を満たした状態。

## 前進条件

- `進行中` へは、次回着手前オーケストレーション記録がすべて確定した同一更新以降でなければ遷移してはならない。
- `レビュー` は、必要な複数レビュー担当の起動または役割別フォールバックが成立し、役割分割が記録されていない限り開始してはならない。
- 実装差分の `レビュー` は、`構造レビュー担当`、`運用整合レビュー担当`、`セキュリティレビュー担当`、`仕様適合レビュー担当` の各役割で、起動または役割別フォールバックが成立していない限り開始してはならない。
- executable behavior を含む作業では、対象コードパスまたは直接必要な隣接コードパスに実コード差分がない限り、`確認`、`レビュー`、`実装状態` を前進させてはならない。
- 文書差分だけで前進できるのは、明示的な文書作業または整合維持のための文書面に限る。

## 必須証跡

`確認`、`レビュー`、`実装状態` を前進させる変更セットには、同時に次を含める。

- 対象差分識別子
- 確認手順と結果
- 複数レビュー担当の役割一覧
- 役割別フォールバック記録（フォールバックがある場合。`対象役割`、`起動失敗理由`、`起動失敗証跡`、`代替実行者`、`代替実行者 agent/run 識別子`、`no-reuse 規則充足根拠` の6項目を必須で含む）
- 実装担当の `agent/run` 識別子
- 各レビュー担当の `agent/run` 識別子
- 進捗判定担当の `agent/run` 識別子
- レビュー担当ごとの判定
- 集約後のレビュー判定と差戻し有無
- セキュリティ上の所見と、その解消有無
- 仕様適合上の所見と、その解消有無
- 未実施項目がある場合の理由

欠落がある前進遷移は無効とする。
