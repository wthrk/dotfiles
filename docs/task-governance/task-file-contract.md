# タスクファイル契約

この文書は、タスクファイルが持つべき情報と、台帳と作業定義文書の責務分離を定義する。

## タスクファイルの責務

タスクファイルは進捗台帳であり、現在値と参照先を保持する。長い手順本文や詳細な作業定義を抱えてはならない。

## タスクファイルに必須の項目

- `現在の作業項目`
- `現在の着手コードパス` または `現在の着手文書パス`
- 各作業項目の `状態`
- 各作業項目の `主成果物`
- 各作業項目の `対象コードパス` または `対象文書パス`
- 各作業項目の `作業定義文書` 参照
- 各作業項目の `粗粒度進捗` 参照
- 各作業項目の `次回着手前オーケストレーション記録`
- 各作業項目の `実装状態`
- 各作業項目の固定実装単位トラッカーまたは同等の進捗面

## 次回着手前オーケストレーション記録に必須の項目

- `実装担当`
- `実装担当 agent/run` 識別子
- `レビュー担当一覧`
- 各レビュー担当の `役割名`
- 各レビュー担当の `agent/run` 識別子
- `進捗判定担当`
- `進捗判定担当 agent/run` 識別子
- `着手順序`
- `役割別フォールバック記録`（フォールバックがある場合は必須）
- `現行対象再読確認`

`レビュー担当一覧` は 1 件では不足とし、複数件を必須とする。
実装差分では最低でも `構造レビュー担当`、`運用整合レビュー担当`、`セキュリティレビュー担当`、`仕様適合レビュー担当` を含める。
`役割別フォールバック記録` には、`対象役割`、`起動失敗理由`、`起動失敗証跡`、`代替実行者`、`代替実行者 agent/run 識別子`、`no-reuse 規則充足根拠` の6項目を必須で含める。
`現行対象再読確認` は、主成果物が `実コード差分` の作業ではコード再読記録、主成果物が `文書差分` の作業では文書再読記録を記載する。

## 作業定義文書に置く内容

次の内容はタスクファイルではなく、作業定義文書に置く。

- `作業種別`
- `作業目的`
- `構造完了条件`
- `既存実装の流用方針`
- `規約違反の解消対象`
- `レビュー合格条件`
- 作業項目固有の境界条件や停止条件

## 重複禁止

- タスクファイルは作業定義文書の本文を再掲してはならない。
- 作業定義文書は状態値や次回着手前記録の正本を持ってはならない。
- 一般的な進め方、状態遷移、完了判定はタスクファイルにも作業定義文書にも再掲せず、共通ガイドラインを参照する。
