# タスクファイル契約

この文書は、root active ledger と領域台帳に必要な最小情報を定義する。

## タスクファイルの責務

- タスク台帳は「何を、どこまで、どの証跡で確認できるか」を保持する。
- 詳細手順や重複説明は持たない。

## タスクファイルに必須の項目（最小）

### root active ledger（`docs/tasks/tasks.md`）

- `現在の作業項目`
- `各作業項目一覧`
- `各作業項目の状態`
- `各作業項目の主成果物`
- `対象コードパス` または `対象文書パス`
- `作業定義文書` 参照
- `レビュー記録` 参照

`現在の作業項目` は `各作業項目一覧` 内の実在する項目名と一致しなければならない。オーケストレーターは、まず root active ledger である `docs/tasks/tasks.md` の `現在の作業項目` を読んで active work item を 1 件確定し、その項目について `状態`、`主成果物`、`対象コードパス/対象文書パス`、`作業定義文書`、`レビュー記録` を順に読む。active work item が `docs/tasks/<area>/tasks.md` を参照している場合は、その領域台帳を必ず読む。
active item 選定時のオーケストレーター読み取りは、台帳フィールド値の取得と参照先の存在確認だけに限定する。`作業定義文書` と `レビュー記録` の本文読み取りは役割起動前に行ってはならない。
active work item 確定後、オーケストレーターが最初に行う処理は役割起動（または起動/利用失敗の記録）でなければならない。起動成功/失敗の扱いが確定する前に、実装判定目的で対象コード・仕様・テスト・レビュー成果物を読んだり、テストを実行したり、ファイルを編集してはならない。
active work item が完了したら、次回実行前に `docs/tasks/tasks.md` の `現在の作業項目` を次の未完了項目へ進める。

### 領域台帳/履歴（`docs/tasks/<area>/tasks.md`）

- `各作業項目一覧`
- `各作業項目の状態`
- `各作業項目の主成果物`
- `対象コードパス` または `対象文書パス`
- `作業定義文書` 参照
- `レビュー記録` 参照

各作業項目ブロックでは、`レビュー記録` 参照を独立した項目として明示し、固定実装単位トラッカーや補助表だけに埋め込んではならない。

`docs/tasks/<area>/tasks.md` は active work item 選定子（`現在の作業項目`）を持たない。active work item の選定は `docs/tasks/tasks.md` のみを正本とする。

## 任意項目

次は必要な場合のみ記載する。

- 粗粒度進捗参照（`issue-*.md`）
- 固定実装単位トラッカー
- 補足メモ

## 作業定義文書に置く内容

- 目的、完了条件、境界条件、停止条件
- 作業項目固有の制約

## オーケストレーターの読み取り境界

- `docs/tasks/tasks.md` は「active work item を特定して委譲判断するための root active ledger」であり、実装詳細・レビュー本文・設計本文の置き場ではない。
- `docs/tasks/<area>/tasks.md` は、active work item が参照している場合に限って読む領域台帳/履歴であり、root active ledger の代替ではない。
- オーケストレーターは root active ledger から active work item と委譲に必要な最小情報を取得し、その項目が要求する領域資料を参照して委譲境界を確定する。実装、レビュー、進捗判定、完了判定そのものは担当役割へ委譲する。
- 利用者依頼がタスク実行コマンドである場合、オーケストレーターは委譲可否の追加許可を利用者へ求めず、上記境界に従って役割起動または起動失敗記録へ進む。

## 重複禁止

- 同じ判定事実を複数文書へ必須重複させない。
- レビュー結果はレビュー記録を正本とする。
- 台帳はレビュー証跡への参照を保持すれば足りる。
- 台帳契約は、後付けの文書書換えだけで満たせる形式条件を要求してはならない。exact file-set/file-count ledger、重複 scope ledger、actor/run bookkeeping などは、実行境界、レビュー品質、検証正確性を具体的に改善する場合に限って要求できる。
