判定: 合格
判定要約: 所見なし
根拠:
- レビュー対象: 現行ブランチ `fix/bws-provisioning-inputs-issue-44` の未コミット worktree を含む current worktree。構造レビュー担当として `docs/architecture/hexagonal-implementation-rules.md`、`docs/architecture/review-checklist.md`、`docs/task-governance/implementation-review-judgement.md`、および BWS 設計責務境界を現行コードへ直接照合した。
- r2 未解消 finding の確認: `rust/dotfiles-cli/src/secrets/support/protection/bws.rs` は `BwsClientSession`、`login_client_with_access_token`、`get_secret_value` による BWS SDK login/get の保護境界だけを持ち、`PasswordStoreRemote` domain 型も `PasswordStoreRemote::parse` も保持していない。同 file は access token の owned plaintext buffer 作成、SDK login、SDK secret value の `Zeroizing<String>` 移動、core dump 抑止 session に限定され、固定 secret key/name の意味づけ、一意解決、0件/複数件 failure 化、取得対象の過不足判定、外部確認 plan を決めていない。
- adapter 哲学質問への回答: `rust/dotfiles-cli/src/secrets/adapters/bw.rs` はこのコードが SDK project/secret/list/get/create/update と `BwsClientPort` 境界型の翻訳だけをしている。外部 API 返却値から `PasswordStoreRemote` への翻訳は adapter の port 実装内で `PasswordStoreRemote::parse` を呼ぶ形になっており、support へ委譲していない。UUID parse、SDK request scope 取得、create/update request 構築、revision/value digest guard 化は SDK/API 変換または stale overwrite port 契約の実装であり、project/secret lookup の一意解決や verify plan を adapter が決めていない。
- support 哲学質問への回答: `rust/dotfiles-cli/src/secrets/support/protection/bws.rs` はこのコードが secret 保護境界を閉じる backend 操作だけをしている。BWS SDK 名は出るが、平文 access token を SDK 呼び出し直前に所有 buffer 化し、呼び出し後に zeroize するための dedicated backend 操作であり、domain object 操作や固定 BWS secret の対象同一性判断は含まない。
- domain 哲学質問への回答: `rust/dotfiles-cli/src/secrets/domain/bws.rs` はこのコードが固定 project/secret name、一意解決、0件/複数件の failure 化を domain rule として保持している。`rust/dotfiles-cli/src/secrets/domain/pass_restore.rs` の `PasswordStoreRemote::parse` は `git@github.com:<owner>/<repo>.git` の業務上の URL 制約を表す domain rule であり、Bitwarden SDK 型や I/O 型へ依存していない。
- application 哲学質問への回答: `run_verify_yubikey_with.rs`、`run_provision_password_store_remote.rs`、`run_register_gpg_backup_primary.rs`、`run_add_gpg_backup_spare.rs` はこのコードが token 取得、project/secret 解決、確認、入力、create/update/fetch の順序と停止分岐だけを扱っている。具体 SDK 型、stdin/println、adapter concrete 型 import は application に存在せず、BWS 外部確認 plan は application の `run_bws_check` にあり、support へ移されていない。
- port 哲学質問への回答: `rust/dotfiles-cli/src/secrets/ports/bw.rs` はこの契約が BWS API 境界へ application が要求する capability と境界型だけを表している。SDK UUID、request DTO、prompt 文言、利用者向け文言は含まず、`fetch_password_store_remote` は取得値を domain 検証済み `PasswordStoreRemote` として返す契約で、平文 access token や raw secret value を application へ返さない。
- adapter 公開面確認: BWS/IO の変更対象 adapter で外部到達する型は `BwsClientAdapter`、`BwLoginAdapter`、`ProcessIoAdapter`、`JsonReportAdapter` など port trait 実装型に限定されている。BWS adapter の helper `envelope_value`、`parse_uuid`、`bws_sdk_request_scope_id`、`build_secret_create_request` は private で、責務は SDK/API 翻訳に限定される。`support/protection/bws.rs` の `BwsClientSession` と `login_client_with_access_token` は support の secret 保護 backend 境界であり、adapter 公開面ではない。
- internal backend stub 確認: `rust/dotfiles-cli/src/secrets/adapters/bw/internal_stub.rs` は `secrets-internal-test-stub` feature 専用で、production build 非混入、compile-time selection、runtime real/stub 分岐なし、同一 `BwsClientPort` 契約、stdout sentinel observation、BWS/YubiKey state 非共有を module comment と実装で満たしている。stub 内の datastore/schema/helper は adapter-local backend stub 内に閉じ、integration test 側へ import される公開 API になっていないため、この存在自体を不合格根拠にしない。
- application 禁止事項確認: `rust/dotfiles-cli/src/secrets/application/` に adapter concrete 型 import はなく、`println!` / `eprintln!` / stdin 直接読み取りは検出されなかった。`run_provision_password_store_remote.rs` の private helper `resolve_remote_url` は `--url` と `PasswordStoreRemoteInputPort` の入力優先順位を適用し、domain rule `PasswordStoreRemote::parse` へ渡す application orchestration helper であり、I/O 実装や SDK 翻訳を持たない。
- 結論: r2 finding の「support/protection/bws.rs が `PasswordStoreRemote` domain 型と `PasswordStoreRemote::parse` を持ち、adapter が外部 API 返却値から port/domain 境界型への翻訳を support へ委譲していた」状態は、現行 worktree では解消されている。BWS 経路の責務配置は、support が保護境界、adapter が SDK/API 翻訳、domain が固定名・一意解決・URL 制約、application が use case 順序と外部確認 plan、port が capability 契約という層境界に収まっている。
