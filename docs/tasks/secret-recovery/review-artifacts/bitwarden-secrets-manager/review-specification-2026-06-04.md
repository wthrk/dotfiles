- `verify-yubikey --check bws` は BWS project/secret の lookup 後に `gpg-secret-key-backup` と `password-store-remote` の両方を解決している。`run_bws_check` は `GpgSecretKeyBackup` と `PasswordStoreRemote` の ID をそれぞれ解決し、envelope fetch、接続中 recipient 照合、`password-store-remote` fetch まで進めるため、BWS secret の取得成功のみで `ok` にしていない（`rust/dotfiles-cli/src/secrets/application/run_verify_yubikey_with.rs:179`）。
- `gpg-secret-key-backup` envelope schema は domain で `serde(deny_unknown_fields)` の wire 型、`version` 固定、`metadata`、`recipients`、`ciphertext`、固定 algorithm、UTC RFC3339、nonce/tag 長、base64、recipient 1 件以上を検証している（`rust/dotfiles-cli/src/secrets/domain/gpg_backup.rs:111`、`rust/dotfiles-cli/src/secrets/domain/gpg_backup.rs:137`、`rust/dotfiles-cli/src/secrets/domain/gpg_backup.rs:189`）。
- `metadata.primary_fingerprint` は wire 保存値では lowercase hex 40 文字、separator なしを厳格検証し、runtime 入力では lowercase hex 40 文字へ正規化する実装になっている（`rust/dotfiles-cli/src/secrets/domain/gpg_backup.rs:556`）。対応する unit test で uppercase、colon、空白、長さ不一致、非 hex を拒否している（`rust/dotfiles-cli/src/secrets/domain/gpg_backup.rs:1420`）。
- 接続中 YubiKey recipient matching は `ConnectedYubiKey` の `serial` と `public_key_fingerprint` を入力にし、`EnvelopeRecipient::matches` が `yubikey_serial` と `public_key_fingerprint` の両一致だけを許可している（`rust/dotfiles-cli/src/secrets/domain/gpg_backup.rs:234`、`rust/dotfiles-cli/src/secrets/domain/gpg_backup.rs:477`）。`run_bws_check` は `resolve_connected_recipient(serial)` 後に `envelope.resolve_recipient` を呼ぶ（`rust/dotfiles-cli/src/secrets/application/run_verify_yubikey_with.rs:193`）。
- unwrap-free recoverability は `verify-yubikey --check bws` で `unwrap_dek` を呼ばず、接続中 recipient identity の解決と一致 recipient の存在だけを確認している。unit test でも `gpg_recipient.expect_unwrap_dek().times(0)` を置き、identity unavailable / recipient mismatch で failure にしている（`rust/dotfiles-cli/src/secrets/application/run_verify_yubikey_with.rs:507`、`rust/dotfiles-cli/src/secrets/application/run_verify_yubikey_with.rs:628`）。
- `password-store-remote fetch` は `run_bws_check` の成功経路で必須になっており、`fetch_password_store_remote` が `pass-id` に対して 1 回呼ばれることを application unit test が固定している（`rust/dotfiles-cli/src/secrets/application/run_verify_yubikey_with.rs:196`、`rust/dotfiles-cli/src/secrets/application/run_verify_yubikey_with.rs:513`）。
- BWS 更新系 stale overwrite prevention は `BackupUpdateGuard` が revision または exact value bytes SHA-256 digest を保持し、`ensure_matches` が同一 guard のときだけ更新を許可する（`rust/dotfiles-cli/src/secrets/domain/gpg_backup.rs:503`）。real BWS adapter は `gpg-secret-key-backup` と `password-store-remote` の更新直前に現行 secret を再取得して guard を照合している（`rust/dotfiles-cli/src/secrets/adapters/bw.rs:161`、`rust/dotfiles-cli/src/secrets/adapters/bw.rs:245`）。spare recipient 追加と pass remote 更新の application tests は guard mismatch を stale overwrite error として停止させている（`rust/dotfiles-cli/src/secrets/application/run_add_gpg_backup_spare.rs:312`、`rust/dotfiles-cli/src/secrets/application/run_provision_password_store_remote.rs:360`）。
- user-facing 前提として `organization` / `machine` / `service account` / `dotfiles-secret-recovery-reader` を要求する公開 CLI option や prompt は確認できなかった。`gpg-backup` / `pass-remote` の公開 option は primary fingerprint、serial、`--url`、`--yes` に限られ、organization/service/machine account 入力はない（`rust/dotfiles-cli/src/secrets.rs:188`）。SDK の `organization_id` 相当は adapter 内で access token から request scope として解決され、利用者入力へ露出していない（`rust/dotfiles-cli/src/secrets/adapters/bw.rs:302`）。
