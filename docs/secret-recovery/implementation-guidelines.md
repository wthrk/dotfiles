# 秘密情報復旧基盤の実装ガイドライン

この文書は、秘密情報復旧基盤で恒久的に参照する実装方針の正本である。計画依頼で使う固定実装単位、役割分担、実装時の境界を定義する。

## 目的と対象範囲

目的は、秘密情報復旧基盤の実装を一貫した層構造、秘密値の所有境界、成果物境界に固定し、secret-recovery 作業全体で同一の判断基準を維持することである。対象は `dotfiles secrets` のコマンドフロー、関連するドメインモデル、ワイヤ形式、ポート、アダプター、補助機能、設計文書である。

## 参照正本

一般構造の判断は [docs/architecture/hexagonal-implementation-rules.md](../architecture/hexagonal-implementation-rules.md) を参照する。機能仕様と保存仕様の判断は [secret-recovery-spec.md](secret-recovery-spec.md) と [yubikey-secret-storage-design.md](yubikey-secret-storage-design.md) を参照する。

## 計画依頼の固定実装単位

secret-recovery の計画実装で扱う実装単位は次の 6 つに固定する。

1. `規約計画`
2. `実装計画`
3. `規約文書更新`
4. `確認`
5. `レビュー`
6. `必要時の後続対応`

## 計画・実装・レビューの役割分担

計画依頼で扱う作業者の役割は、実装担当とレビュー担当に固定する。役割ごとの実施可能範囲は次のとおり。

- 計画: 実装担当だけが `規約計画` と `実装計画` を作成・更新する。レビュー担当は計画本文を編集せず、`レビュー` で合否判定を行う。
- 実装: 実装担当だけが `規約文書更新` と `必要時の後続対応` を実施する。レビュー担当は実装差分を直接編集せず、必要な差戻しを判定する。
- 確認: 実装担当が `確認` を実施する。レビュー担当は確認内容を再確認できる。
- レビュー: レビュー担当だけが `レビュー` の合否判定を確定する。実装担当は差戻し時の再実施を担当する。

## 実装単位ごとの実装方針

### `規約計画`

- 実装内容: 作業項目で適用する規約範囲、参照正本、除外範囲を確定する。
- 分割方針: 作業項目ごとに規約適用点を分け、他作業項目とは独立に扱う。
- 責務境界: 対象作業項目の規約適用範囲、参照正本、除外範囲の定義だけを扱う。
- 荒い受け入れ条件: 参照正本と適用範囲が衝突なく示される。

### `実装計画`

- 実装内容: 対象作業項目で更新する文書・節・成果物と更新順序を確定する。
- 分割方針: `規約文書更新` を作業項目単位で完結する差分に分ける。
- 責務境界: 対象作業項目の更新対象文書・節・成果物と更新順序の定義だけを扱う。
- 荒い受け入れ条件: 更新対象と順序が示される。

### `規約文書更新`

- 実装内容: 計画で確定した対象文書を更新し、語彙と参照を整合させる。
- 分割方針: 対象作業項目に必要な文書差分だけを扱う。
- 責務境界: 対象作業項目に必要な規約文書差分を扱う。
- 荒い受け入れ条件: 必要な文書更新が完了している。

### `確認`

- 実装内容: 更新後文書の整合を確認する。
- 分割方針: 確認対象は対象作業項目に必要な範囲に限定する。
- 責務境界: 対象作業項目に必要な確認だけを扱う。
- 荒い受け入れ条件: レビュー判定に必要な確認が完了している。

### `レビュー`

- 実装内容: 変更差分をレビューし、差戻し有無を判定する。
- 分割方針: 判定は作業項目ごとに行い、不合格時は同じ作業項目で必要な単位を再実施する。
- 責務境界: 対象作業項目の差分に対する合否判定だけを扱う。
- 荒い受け入れ条件: 合格時は後続対応要否が判定され、不合格時は再実施対象が示される。

### `必要時の後続対応`

- 実装内容: レビュー合格後に必要となる最小限の追従更新を行う。
- 分割方針: 後続対応が必要な作業項目だけを対象にする。
- 責務境界: 対象作業項目で必要と判定された追従更新だけを扱う。
- 荒い受け入れ条件: 次回着手に必要な更新が完了している。
