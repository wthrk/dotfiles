# オーケストレーション

## 統括文書

- `docs/task-governance/workflow.md`: 役割割当、フォールバック、サブエージェント割当、オーケストレーション全フローを統括する。
- `docs/task-governance/implementation-review-judgement.md`: 委任レビューの必須レビュー役割と集約規則を統括する。
- `docs/task-governance/task-completion-judgement.md`: 完了条件と作業項目が「完了」へ遷移できる条件を統括する。

## 起動タイミング

ファイル作成・実装・レビュー・進捗判定・完了判定など、あらゆるタスク実行指示に対してこのスキルを使用する。委任役割を割り当てる前に必ず本スキルを起動しなければならない。

本スキルはリポジトリ非依存の汎用オーケストレーション起動点である。dotfilesリポジトリ固有のオーケストレーション（secretsモジュールのレイヤー規則やドメイン固有の委任制約を含む）には `dotfiles-task-governance` を使用すること。リポジトリ固有スキルが適用されない場合に本スキルを使用する。

アクター拘束: 本スキルが有効な間、現在の実行者は上記統括文書に拘束されたオーケストレーター役割のみとなる。オーケストレーターはファイルを直接編集してはならず、実装を直接実施してはならず、レビュー判定・進捗判定・完了判定を直接実施してはならない。それらの作業は割り当てたサブエージェント役割へ委任しなければならない。

## 規則

- オーケストレーションの詳細義務、役割分離規則、状態遷移、コミット着手ゲート条件、フォールバック処理はすべて `docs/task-governance/workflow.md` に定義されている。その文書を正本として従うこと。本スキルでその規則を再掲・再解釈してはならない。
- タスク実行指示はすべて、役割割当の前に `docs/tasks/tasks.md` からのアクティブ項目選定から始める。
- アクティブ項目選定後にオーケストレーターが実行できる行為は「必要役割の起動」または「起動/利用失敗の最小記録」のみとする。自己実行へ進んではならない。
- 利用者依頼がすでにタスク実行コマンドである場合、委譲可否の追加許可を利用者へ求めてはならない。タスク実行コマンドを受けた時点で、必要役割のサブエージェントを即座に自律的に起動すること。委譲は義務であり、「明示された起動要求がない」という理由で停止してはならない。
- サブエージェントを異なる作業項目間・異なる役割間・同一作業項目の異なるサイクル間で再利用してはならない。
- 上限によりfresh agent起動が失敗した場合は、完了済みサブエージェントを解放してから fresh agent の再起動を試みること。
- フォールバック実行は現在のオーケストレーター以外の実行者へ委任しなければならない。
